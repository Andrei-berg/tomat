## Summary

Фаза 3.1 — минимальная: три конкретных UX-исправления без новых зависимостей и без изменений бизнес-логики. Server Action `logout()` уже написан и корректен (`deleteSession()` + `redirect('/login')`). Единственная задача — добавить кнопку «Выйти» на каждую защищённую страницу и добавить навигационные ссылки между разделами.

Все три страницы (`/prices`, `/orders`, `/orders/new`) — Server Components, которые рендерят 'use client' компоненты. Кнопка «Выйти» вызывает Server Action напрямую через `form action={logout}` или `<button formAction={logout}>` — без клиентского компонента. Навигация `/prices` ↔ `/orders` реализуется через `<Link>` в Server Component или отдельным `'use client'` компонентом `<NavBar>` использующим `usePathname()` для подсветки активного раздела.

Критически важный архитектурный факт: `usePathname()` — Client Component hook (импорт из `next/navigation`). Для подсветки активного раздела нужен отдельный `'use client'` компонент — нельзя использовать текущий pathname в Server Component напрямую. Альтернатива — передавать активный раздел как prop из Server Component (через `headers()` или через URL), но это сложнее. Самый простой путь: небольшой `NavBar` клиентский компонент с `usePathname()`.

**Primary recommendation:** Создать `src/components/ui/nav-bar.tsx` (`'use client'`) с `usePathname()` для активного состояния + кнопкой «Выйти» через `form action={logout}`. Подключить этот компонент в header каждой защищённой страницы вместо текущих отдельных back-ссылок.

## Architecture Patterns

### Текущее состояние навигации (что есть)

```
/prices/page.tsx       → нет ссылки на /orders, нет кнопки «Выйти»
/orders/page.tsx       → нет ссылки на /prices, нет кнопки «Выйти»
/orders/new/page.tsx   → есть «← Заказы» ссылка, нет кнопки «Выйти»
/orders/[id]/page.tsx  → есть «← Назад» ссылка, нет кнопки «Выйти»
```

### Целевое состояние (что нужно)

```
Каждая защищённая страница имеет:
  - Навигационные ссылки: [Прайс] [Заказы] с подсветкой активного
  - Кнопка «Выйти» → вызывает logout() Server Action
  - На /prices после сохранения: кнопка «Создать заказ» → /orders/new
```

### Pattern 1: NavBar Client Component с usePathname

```typescript
// src/components/ui/nav-bar.tsx
// Source: next/navigation usePathname — verified in node_modules/next/dist/docs/
'use client'
import Link from 'next/link'
import { usePathname } from 'next/navigation'
import { logout } from '@/app/actions/auth'

export default function NavBar() {
  const pathname = usePathname()

  const navLinks = [
    { href: '/prices', label: 'Прайс' },
    { href: '/orders', label: 'Заказы' },
  ]

  return (
    <nav style={{
      display: 'flex',
      alignItems: 'center',
      justifyContent: 'space-between',
      paddingTop: '20px',
      paddingBottom: '16px',
    }}>
      {/* Section links */}
      <div style={{ display: 'flex', gap: '6px' }}>
        {navLinks.map(({ href, label }) => {
          const active = pathname === href || pathname.startsWith(href + '/')
          return (
            <Link
              key={href}
              href={href}
              style={{
                padding: '7px 14px',
                borderRadius: '8px',
                fontSize: '13px',
                fontWeight: active ? 700 : 500,
                textDecoration: 'none',
                background: active ? 'rgba(200,67,26,0.12)' : 'transparent',
                color: active ? 'var(--mk-accent)' : 'var(--mk-text-2)',
                border: active ? '1px solid rgba(200,67,26,0.2)' : '1px solid transparent',
                transition: 'all 0.15s',
              }}
            >
              {label}
            </Link>
          )
        })}
      </div>

      {/* Logout */}
      <form action={logout}>
        <button
          type="submit"
          style={{
            padding: '7px 14px',
            borderRadius: '8px',
            fontSize: '13px',
            fontWeight: 500,
            background: 'transparent',
            border: '1px solid var(--mk-border)',
            color: 'var(--mk-text-3)',
            cursor: 'pointer',
            fontFamily: 'var(--font-geist-sans)',
          }}
        >
          Выйти
        </button>
      </form>
    </nav>
  )
}
```

**Ключевые детали:**
- `pathname.startsWith(href + '/')` — активен `/orders` когда на `/orders/new` или `/orders/[id]`
- `form action={logout}` — Server Action вызывается нативной HTML формой, работает без JS
- Не нужен `useActionState` для logout — нет состояния ошибки (неверный пароль уже прошёл проверку)

### Pattern 3: Кнопка «Создать заказ» в PricesForm после успешного сохранения

Текущее состояние: `PricesForm` показывает `showSuccess` — зелёная полоска «Цены сохранены», которая исчезает через 2.6 сек. Нужно добавить кнопку «Создать заказ» → `/orders/new` рядом с этим состоянием.

```typescript
// src/components/ui/prices-form.tsx — в блоке showSuccess
import Link from 'next/link'

// В JSX после `showSuccess &&`:
{showSuccess && (
  <>
    <div style={{ /* существующий success banner */ }}>
      <CheckIcon />
      Цены сохранены
    </div>
    <Link
      href="/orders/new"
      style={{
        display: 'flex',
        alignItems: 'center',
        justifyContent: 'center',
        width: '100%',
        height: '50px',
        borderRadius: '14px',
        background: 'linear-gradient(135deg, var(--mk-accent) 0%, var(--mk-accent-hi) 100%)',
        color: 'white',
        fontSize: '15px',
        fontWeight: 600,
        textDecoration: 'none',
        letterSpacing: '-0.01em',
        fontFamily: 'var(--font-geist-sans)',
        boxShadow: '0 6px 24px var(--mk-accent-glow)',
        animationName: 'mkUp',
        animationDuration: '0.3s',
        animationFillMode: 'both',
      }}
    >
      Создать заказ →
    </Link>
  </>
)}
```

Кнопка видна пока виден success banner (2.6 сек). Альтернатива: не скрывать автоматически success state когда `showSuccess` истинно, а оставлять кнопку постоянно. Это даёт лучший UX — пользователь успевает нажать кнопку.

**Рекомендация**: изменить логику `setShowSuccess` — при наличии success больше не скрывать автоматически, или увеличить таймаут до 8 сек. Более простой вариант: вынести `showSuccess` в отдельное вечное состояние `savedToday` которое сбрасывается только при следующем изменении форм.

Самый простой вариант: убрать автоскрытие (убрать `setTimeout`), кнопка «Создать заказ» остаётся до следующего изменения цен.

### Pattern 4: Logout через form action (без useActionState)

```typescript
// Source: Next.js 16 authentication.md guide (verified)
// В NavBar или прямо в header:

import { logout } from '@/app/actions/auth'

// Вариант A: отдельная форма (в Server Component или Client Component)
<form action={logout}>
  <button type="submit">Выйти</button>
</form>

// Вариант B: в Client Component через startTransition (если нужно pending state)
import { useTransition } from 'react'
import { logout } from '@/app/actions/auth'

function LogoutButton() {
  const [isPending, startTransition] = useTransition()
  return (
    <button
      type="button"
      onClick={() => startTransition(() => logout())}
      disabled={isPending}
    >
      {isPending ? 'Выхожу...' : 'Выйти'}
    </button>
  )
}
```

Для этого проекта **вариант A** достаточен — logout мгновенный, pending state не нужен.

### Anti-Patterns to Avoid

- **НЕ использовать `usePathname` в Server Component** — это Client-only hook, вызовет ошибку. NavBar должен быть `'use client'`.
- **НЕ импортировать `useRouter` из `next/router`** — в App Router импорт только из `next/navigation`. Но для этой фазы useRouter вообще не нужен.
- **НЕ добавлять logout в каждую страницу по-отдельному** — создать один `NavBar` компонент, переиспользовать.
- **НЕ передавать `active` prop из Server Component** — ненужное усложнение. `usePathname()` в NavBar сам определяет активный раздел.
- **НЕ прятать «Создать заказ» через 2.6 сек** — кнопка должна оставаться доступной. Убрать автоскрытие success state или существенно увеличить таймаут.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Определение активного раздела | Передавать `activeRoute` prop из Server Component через headers/cookies | `usePathname()` в Client Component | Встроен в Next.js, доступен в любом Client Component |
| Вызов logout | Отдельный API route `/api/logout` | Server Action `logout()` через `form action={}` | Уже существует, App Router pattern, без fetch |

**Key insight:** Весь нужный инструментарий уже в проекте. Фаза — это сборка из готовых кирпичей, не создание нового.

## Common Pitfalls

### Pitfall 1: NavBar active state на /orders/new и /orders/[id]

**What goes wrong:** `pathname === '/orders'` не совпадает когда пользователь на `/orders/new` или `/orders/abc`.
**Why it happens:** Точное сравнение pathname.
**How to avoid:** Использовать `pathname.startsWith('/orders')` для раздела «Заказы» — тогда NavBar подсвечивает «Заказы» на всех вложенных маршрутах.
**Warning signs:** «Заказы» не подсвечено когда на /orders/new.

### Pitfall 2: NavBar гидрация и rewrites

**What goes wrong:** В Next.js docs упомянуто: если есть rewrites в `next.config` или `proxy` файл, `usePathname()` может дать hydration mismatch на первый рендер.
**Why it happens:** Proxy (`src/proxy.ts`) существует в проекте. Значение pathname на сервере может не совпадать с браузерным.
**How to avoid:** Проверить — proxy делает только redirect (не rewrite), поэтому после редиректа pathname в браузере совпадает с серверным. Hydration mismatch маловероятен. Если возникает — обернуть NavBar в `<Suspense>` или использовать `typeof window !== 'undefined'` guard.
**Warning signs:** Консольная ошибка hydration mismatch после навигации.

### Pitfall 3: form action={logout} в Client Component

**What goes wrong:** `logout` — Server Action. Импортированный в Client Component (`NavBar`) должен быть корректно помечен `'use server'` в своём файле.
**Why it happens:** Next.js требует явной границы `'use server'` для Server Actions.
**How to avoid:** `src/app/actions/auth.ts` уже имеет `'use server'` директиву вверху файла — импорт из него в Client Component корректен и будет работать.
**Warning signs:** Runtime error «logout is not a function» или ошибка сборки.

### Pitfall 4: Кнопка «Создать заказ» исчезает до нажатия

**What goes wrong:** `setTimeout(() => setShowSuccess(false), 2600)` скрывает success banner и кнопку через 2.6 сек.
**Why it happens:** Существующая логика автоскрытия.
**How to avoid:** Убрать таймаут или увеличить до достаточного значения. Рекомендуется убрать автоскрытие полностью — кнопка «Сохранить» всегда доступна, пользователь может сохранить снова. Success state сбрасывается при следующем изменении values через `useEffect`.
**Warning signs:** Пользователь видит success на долю секунды и кнопка исчезает.

### Pitfall 5: Отсутствие `fontFamily` в стилях NavBar

**What goes wrong:** Кнопки и ссылки NavBar не используют шрифт `var(--font-geist-sans)`, выглядят иначе.
**Why it happens:** CSS-переменная шрифта устанавливается в `html` элементе через className, но кнопки имеют системный шрифт по умолчанию.
**How to avoid:** Добавить `fontFamily: 'var(--font-geist-sans)'` на каждый `<button>` и `<Link>` в NavBar — паттерн из существующих компонентов.
**Warning signs:** Шрифт кнопок отличается от остального UI.

## Open Questions

1. **Стоит ли показывать «Выйти» на странице /login?**
   - What we know: Proxy редиректит аутентифицированных пользователей с /login обратно. Неаутентифицированный пользователь не увидит кнопку «Выйти».
   - Recommendation: NavBar только на защищённых страницах. Страница /login не меняется.

2. **Нужна ли NavBar на странице /orders/[id]?**
   - What we know: Там уже есть «← Назад» ссылка. Success criteria говорят только о `/prices` и `/orders`.
   - Recommendation: Добавить NavBar и на /orders/[id] для единообразия. Убрать «← Назад» или оставить вместе — решить при планировании.

3. **Автоскрытие success state в PricesForm**
   - What we know: Текущий `setTimeout 2600ms` скроет кнопку «Создать заказ» слишком быстро.
   - Recommendation: Убрать `setTimeout` полностью из `setShowSuccess`. Success state сбрасывается при следующем `saveState?.success` обновлении (т.е. при следующем сохранении). Это безопаснее.
