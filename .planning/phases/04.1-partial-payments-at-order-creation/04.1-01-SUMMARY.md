## Accomplishments
- `calcEffective` imported from `@/lib/dal` — reuses existing effective total logic
- `prepayment_amount` and `prepayment_type` read from formData in `createOrder`
- If `payment_type === 'debt'` and `prepayment_amount > 0`: inserts into `debt_payments`, updates `orders.status` to `'partial'` or `'paid'`
- Failed `debt_payments` insert is silently ignored — order creation still returns `{ success: true }`
- `/debts` and `/debtors` revalidated after any successful prepayment

## Decisions Made
- Prepayment is best-effort: a failed `debt_payments` insert does not prevent the order from being created. Seller can record payment via /debts/[clientId] later.
- Server caps `safeAmount = Math.min(prepaymentRaw, effectiveAmt)` — prevents overpayment regardless of what the UI sends.
- `prepaymentType` defaults to `'cash'` for any value other than `'card'` (explicit `=== 'card' ? 'card' : 'cash'` guard).
