## Summary

Phase 04.1 goal is fully achieved. The `createOrder` Server Action was extended with a best-effort prepayment block that runs after both `orders` and `order_items` inserts succeed. It reads `prepayment_amount` and `prepayment_type` from FormData, caps the amount server-side via `Math.min`, inserts into `debt_payments`, and updates `orders.status` to `'partial'` or `'paid'`. A failed `debt_payments` insert is silently ignored — the order is never at risk.

`OrderForm` was extended with a conditional Section 4.5 that appears only when `paymentType === 'debt'`. The amount input is capped at `effective` (both via `max` attribute and server `Math.min`). `buildFormData()` passes both prepayment fields when present. `resetForm()` clears both fields. All wiring is complete, TypeScript compiles cleanly, and browser verification was approved by the user.
